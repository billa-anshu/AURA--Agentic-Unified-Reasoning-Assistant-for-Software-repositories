## 1. Overall purpose and architecture

This application is a virtual tour creation and viewing platform that allows users to upload room images, stitch them into panoramic views, and navigate through them using a 3D interface [cite:file=backend/stitcher.py;symbol=images;lines=17-17]. The system serves content creators who need to build immersive digital tours and end-users who wish to explore these environments [cite:file=frontend/src/pages/AllToursPage.js;symbol=AllToursPage;lines=5-45]. The technology stack consists of a React frontend for user interaction and a Python Flask backend for server-side processing, with Supabase acting as the central data store and authentication provider [cite:file=frontend/src/pages/TourEditorPage.js;symbol=showConfirmation;lines=70-110]. The codebase is primarily composed of JavaScript for the frontend logic, Python for the backend services, and image assets that constitute the bulk of the repository files [cite:file=backend/app.py;symbol=files;lines=290-290].

The architecture follows a client-server model where the frontend handles UI state and user events, while the backend manages business logic and external service integration. The project is organized into two main directories: `frontend` and `backend`. The `frontend` folder contains the React application, including pages for login, tour creation, and viewing, as well as components for modals and protected routes [cite:file=frontend/src/pages/Login.js;symbol=handleLogin;lines=12-52]. The `backend` folder contains the Flask application, configuration files, and the logic for processing and storing tour assets [cite:file=backend/app.py;symbol=files;lines=290-290]. Data persistence is handled through Supabase, which abstracts the underlying database and storage logic, allowing both the frontend and backend to perform CRUD operations without managing raw SQL or file system details directly [cite:file=backend/app.py;symbol=panorama_url;lines=166-166] [cite:file=frontend/src/pages/TourEditorPage.js;symbol=y;lines=554-594]. The backend also utilizes local temporary storage folders for intermediate file processing before uploading assets to the cloud [cite:file=backend/app.py;symbol=UPLOAD_FOLDER;lines=23-23].

## 2. Key components/modules

*   **Frontend Authentication and Navigation**: The `Login.js` and `Signup.js` pages handle user identity management [cite:file=frontend/src/pages/Signup.js;symbol=handleSignup;lines=12-52]. The `handleLogin` function authenticates users by calling `supabase.auth.signInWithPassword` and verifies email confirmation status before granting access [cite:file=frontend/src/pages/Login.js;symbol=handleLogin;lines=12-52]. Similarly, `handleSignup` processes registration via `supabase.auth.signUp` and manages error states for new accounts [cite:file=frontend/src/pages/Signup.js;symbol=handleSignup;lines=12-52]. The `Home.js` page includes a `handleCreateClick` function that checks authentication status; if the user is not logged in, it redirects them to the login page, otherwise it navigates to the tour creation route [cite:file=frontend/src/pages/Home.js;symbol=handleCreateClick;lines=8-48].

*   **Tour Creation and Management**: The `VirtualTourForm.js` component allows users to create new tours by generating a unique `tourId` using `uuidv4` and managing room names and image uploads [cite:file=frontend/src/pages/VirtualTourForm.js;symbol=VirtualTourForm;lines=6-46]. It uses `FileReader` to process file inputs and create image previews for the user [cite:file=frontend/src/pages/VirtualTourForm.js;symbol=VirtualTourForm;lines=6-46]. The `AllToursPage.js` component displays a list of available tours by fetching `tour_id` and `tour_name` from the Supabase `tour` table, ordered by creation date [cite:file=frontend/src/pages/AllToursPage.js;symbol=AllToursPage;lines=5-45].

*   **Tour Editing and Asset Management**: The `TourEditorPage.js` is the primary interface for modifying existing tours [cite:file=frontend/src/pages/TourEditorPage.js;symbol=TourEditorPage;lines=27-67]. It uses `useParams` to identify the specific tour and `useRef` to manage panorama references [cite:file=frontend/src/pages/TourEditorPage.js;symbol=TourEditorPage;lines=27-67]. Within this page, the `handleAudioFileChange` function updates local state by storing selected audio files and clearing previous recordings for specific rooms [cite:file=frontend/src/pages/TourEditorPage.js;symbol=handleAudioFileChange;lines=245-285]. The `handleRemoveMarker` function deletes navigation markers from the Supabase `markers` table after prompting the user for confirmation [cite:file=frontend/src/pages/TourEditorPage.js;symbol=handleRemoveMarker;lines=497-537]. Additionally, `handleSelectRoomForTooltipEdit` prepares the UI for editing tooltips by resetting inputs for new content and placement positions [cite:file=frontend/src/pages/TourEditorPage.js;symbol=handleSelectRoomForTooltipEdit;lines=528-568]. When placing tooltips, the application calculates normalized coordinates (`x`, `y`) based on the image's bounding rectangle and inserts records into the `tooltips` table via the Supabase client [cite:file=frontend/src/pages/TourEditorPage.js;symbol=y;lines=554-594] [cite:file=frontend/src/pages/TourEditorPage.js;symbol=x;lines=553-593].

*   **Backend Processing and Storage**: The `backend/app.py` file serves as the processing layer [cite:file=backend/app.py;symbol=app;lines=18-18]. The `get_tour_data_endpoint` retrieves specific tour data, such as the `start_room`, from the Supabase `tour` table and returns it as a JSON response [cite:file=backend/app.py;symbol=get_tour_data_endpoint;lines=502-631]. The `delete_audio_endpoint` processes POST requests to delete audio files from Supabase Storage by extracting `tourId` and `roomName` from the JSON payload [cite:file=backend/app.py;symbol=delete_audio_endpoint;lines=781-813]. The backend also manages the stitching process, where it uploads stitched panoramas to Supabase Storage and stores the resulting `panorama_url` for retrieval [cite:file=backend/app.py;symbol=panorama_url;lines=166-166]. Configuration constants like `UPLOAD_FOLDER` and `TEMP_OUTPUT_FOLDER` are used to handle temporary local storage for intermediate files [cite:file=backend/app.py;symbol=UPLOAD_FOLDER;lines=23-23]. During tour creation, the backend checks if a tour exists in the database and inserts a new entry using the `tour_name` from the request form if necessary [cite:file=backend/app.py;symbol=tour_name;lines=223-223].

*   **Virtual Tour Viewing**: The `PanoramaViewer.js` component serves as the primary interface for users to navigate the virtual tour [cite:file=frontend/src/pages/PanoramaViewer.js;symbol=PanoramaViewer;lines=15-55]. It initializes a 3D viewer, manages node states, and handles audio playback for specific locations using the `tourId` retrieved from route parameters [cite:file=frontend/src/pages/PanoramaViewer.js;symbol=PanoramaViewer;lines=15-55].
