## 1. Overall purpose and architecture

The application is a web-based presentation editor that allows users to create, manage, and export slide decks, featuring AI-powered generation and image transformation capabilities. It is built using a Next.js stack with TypeScript, where the frontend consists primarily of React components (73% of the codebase is `.tsx` files) and the backend logic resides in Next.js API routes [cite:file=app/workspace/page.tsx;symbol=fetchProjects;lines=28-68] [cite:file=app/api/projects/route.ts;symbol=POST;lines=30-56]. The system follows a client-server architecture where the browser-based interface initiates HTTP requests to server-side handlers, which then interact with a Firestore database for persistence [cite:file=app/workspace/page.tsx;symbol=fetchProjects;lines=28-68] [cite:file=app/api/projects/route.ts;symbol=POST;lines=30-56].

The folder structure separates concerns between the `app` directory, which contains routing and API endpoints, and the `components` directory, which houses reusable UI elements and feature-specific modules [cite:file=components/editor/ai-generation-dialog.tsx;symbol=AIGenerationDialog;lines=17-57] [cite:file=app/api/projects/route.ts;symbol=GET;lines=5-45]. The `app/api` folder contains route handlers for distinct operations such as project management, user authentication, and slide generation [cite:file=app/api/projects/route.ts;symbol=GET;lines=5-45] [cite:file=app/api/generate-slide/route.ts;symbol=POST;lines=7-47]. The `components/editor` folder contains the core editing tools, while `components/ui` provides foundational layout and form primitives [cite:file=components/editor/floating-action-tool.tsx;symbol=FloatingActionTool;lines=14-54] [cite:file=components/ui/sidebar.tsx;symbol=SidebarInset;lines=307-347]. Authentication acts as a middleware guard in the API layer, where protected routes verify user identity via an `auth()` function before executing business logic [cite:file=app/api/generate-slide/route.ts;symbol=POST;lines=7-47] [cite:file=app/api/users/route.ts;symbol=POST;lines=30-70].

## 2. Key components/modules

*   **`app/api/projects`**: This module handles the CRUD operations for user presentations. The `GET` handler retrieves the list of projects for the authenticated user by querying the Firestore `projects` collection [cite:file=app/api/projects/route.ts;symbol=GET;lines=5-45]. The `POST` handler creates new project documents, verifying the user's identity and using `addDoc` to persist the data [cite:file=app/api/projects/route.ts;symbol=POST;lines=30-56].
*   **`app/api/generate-slide`**: This route serves as the backend entry point for AI slide generation. The `POST` handler authenticates the user and retrieves their document data from Firestore to process the generation request [cite:file=app/api/generate-slide/route.ts;symbol=POST;lines=7-47].
*   **`app/api/users`**: This module manages user profiles and registration. The `POST` handler creates new user documents with initial fields like `credits` and `isSubscribed` [cite:file=app/api/users/route.ts;symbol=POST;lines=30-70]. The `PUT` handler updates existing user records using `updateDoc` to merge new profile data [cite:file=app/api/users/route.ts;symbol=PUT;lines=59-79].
*   **`components/editor/ai-generation-dialog`**: This React component provides the interface for initiating AI slide creation. It manages local state for the prompt and slide count, and the `handleGenerate` function sends a POST request to the `/api/generate-slide` endpoint [cite:file=components/editor/ai-generation-dialog.tsx;symbol=AIGenerationDialog;lines=17-57] [cite:file=components/editor/ai-generation-dialog.tsx;symbol=handleGenerate;lines=25-65].
*   **`components/editor/outline-editor`**: The `OutlineEditor` component displays a list of slides, allowing users to select, add, or delete individual slides to manage the presentation structure [cite:file=components/editor/outline-editor.tsx;symbol=OutlineEditor;lines=21-61].
*   **`components/editor/design-style-selector`**: This component renders a modal for choosing visual design styles [cite:file=components/editor/design-style-selector.tsx;symbol=DesignStyleSelector;lines=51-91]. It triggers the `onStyleChange` callback, which is handled by `handleDesignStyleChange` in the editor page to persist the new style [cite:file=components/editor/design-style-selector.tsx;symbol=DesignStyleSelector;lines=51-91] [cite:file=app/workspace/editor/[id]/page.tsx;symbol=handleDesignStyleChange;lines=124-164].
*   **`components/editor/image-transform-dialog`**: This component allows users to apply transformations to images. It handles the asynchronous process of transforming images and updating the preview, integrating with the image processing service [cite:file=components/editor/image-transform-dialog.tsx;symbol=ImageTransformDialog;lines=23-63].
*   **`components/editor/floating-action-tool`**: The `FloatingActionTool` renders a fixed-position button that expands to reveal quick-action tools like image transformation and content improvement [cite:file=components/editor/floating-action-tool.tsx;symbol=FloatingActionTool;lines=14-54].
*   **`components/ui/carousel`**: This module wraps the Embla Carousel library to provide a responsive, scrollable container [cite:file=components/ui/carousel.tsx;symbol=Carousel;lines=45-85]. The `useCarousel` hook provides access to the internal context, throwing an error if used outside a valid `Carousel` parent [cite:file=components/ui/carousel.tsx;symbol=useCarousel;lines=35-75] [cite:file=components/ui/carousel.tsx;symbol=Carousel;lines=45-85].
*   **`components/ui/sidebar`**: This module defines the layout structure, with `SidebarInset` managing the main content area and `SidebarRail` providing a toggle button to expand or collapse the navigation panel [cite:file=components/ui/sidebar.tsx;symbol=SidebarInset;lines=307-347] [cite:file=components/ui/sidebar.tsx;symbol=SidebarRail;lines=282-322].
*   **`lib/imagekit`**: This utility module contains the `buildImageKitUrl` function, which constructs ImageKit URLs by appending transformation parameters like width and height to the base image URL [cite:file=lib/imagekit.ts;symbol=buildImageKitUrl;lines=7-44].
*   **`hooks/use-toast`**: This hook manages toast notifications, using the `genId` function to generate unique string identifiers for each notification to ensure they can be individually tracked [cite:file=hooks/use-toast.ts;symbol=genId;lines=27-67].

## 3. Notable functions/classes

The `AIGenerationDialog` component serves as the primary interface for initiating AI-driven content creation by managing local state for the user's prompt, desired slide count, and loading status [cite:file=components/editor/ai-generation-dialog.tsx;symbol=AIGenerationDialog;lines=17-57]. Upon form submission, it triggers the `handleGenerate` function, which validates that the prompt is not empty before proceeding [cite:file=components/editor/ai-generation-dialog.tsx;symbol=handleGenerate;lines=25-65]. This function then sets the loading state to true and sends a POST request to the `/api/generate-slide` endpoint, passing the prompt, slide count, and streaming preference as parameters [cite:file=components/editor/ai-generation-dialog.tsx;symbol=handleGenerate;lines=25-65]. On the server side, the `POST` handler in the generate-slide route first verifies user authentication via the `auth()` function to ensure only authorized users can access the service [cite:file=app/api/generate-slide/route.ts;symbol=POST;lines=7-47]. It then retrieves the user's document data from the Firestore database to process the generation request, acting as the bridge between the frontend dialog and the AI service [cite:file=app/api/generate-slide/route.ts;symbol=POST;lines=7-47].

For project management, the `fetchProjects` function operates within a `useEffect` hook on the workspace page, fetching data from the `/api/projects` endpoint upon component mount [cite:file=app/workspace/page.tsx;symbol=fetchProjects;lines=28-68]. The corresponding `GET` handler in the projects route queries the Firestore `projects` collection, filtering documents where the `createdBy` field matches the authenticated user's ID [cite:file=app/api/projects/route.ts;symbol=GET;lines=5-45]. When creating new projects, the `POST` handler in the projects route constructs a new document containing the title, description, and metadata, using `addDoc` to persist this data into the database [cite:file=app/api/projects/route.ts;symbol=POST;lines=30-56].

The `DesignStyleSelector` component renders a modal dialog that allows users to choose a visual design style from a grid of options [cite:file=components/editor/design-style-selector.tsx;symbol=DesignStyleSelector;lines=51-91]. When a user selects a style, it triggers the `handleDesignStyleChange` function, which updates the application's design style state and immediately persists the change by calling `saveProject` with the current slides, title, and new style [cite:file=app/workspace/editor/[id]/page.tsx;symbol=handleDesignStyleChange;lines=124-164]. For image manipulation, the `ImageTransformDialog` component provides an input for the image URL and a selector for the transformation type, handling the asynchronous process of transforming the image [cite:file=components/editor/image-transform-dialog.tsx;symbol=ImageTransformDialog;lines=23-63]. The `buildImageKitUrl` utility function supports this by constructing an ImageKit URL with transformation parameters such as width, height, and quality, returning the original URL if the service is not configured [cite:file=lib/imagekit.ts;symbol=buildImageKitUrl;lines=7-44].

The `Carousel` component wraps the Embla Carousel library to provide a responsive, scrollable container for displaying content [cite:file=components/ui/carousel.tsx;symbol=Carousel;lines=45-85]. It exposes an API for controlling navigation and selection, which is accessed by child components through the `useCarousel` custom hook [cite:file=components/ui/carousel.tsx;symbol=useCarousel;lines=35-75]. This hook ensures proper component hierarchy by throwing an error if the context is missing, enforcing that it is used within a valid `<Carousel />` parent [cite:file=components/ui/carousel.tsx;symbol=useCarousel;lines=35-75].

## 4. Data flow and design patterns

A concrete end-to-end request flow begins when a user submits a prompt in the `AIGenerationDialog` component [cite:file=components/editor/ai-generation-dialog.tsx;symbol=AIGenerationDialog;lines=17-57]. The `handleGenerate` function captures this input and sends a POST request to the `/api/generate-slide` endpoint [cite:file=components/editor/ai-generation-dialog.tsx;symbol=handleGenerate;lines=25-65]. The server-side `POST` handler receives this request and first executes the `auth()` function to verify the user's identity [cite:file=app/api/generate-slide/route.ts;symbol=POST;lines=7-47]. If authentication fails, the system rejects the request; if successful, it retrieves the user's document using `getDoc` to check their current status or credits before proceeding with generation logic [cite:file=app/api/generate-slide/route.ts;symbol=POST;lines=7-47]. This pattern demonstrates the **Middleware** or guard pattern, where every protected route begins by calling `auth()` and checking for a valid `userId` before executing further logic [cite:file=app/api/generate-slide/route.ts;symbol=POST;lines=7-47] [cite:file=app/api/users/route.ts;symbol=POST;lines=30-70] [cite:file=app/api/users/route.ts;symbol=PUT;lines=59-79] [cite:file=app/api/projects/route.ts;symbol=POST;lines=30-56] [cite:file=app/api/imagekit-auth/route.ts;symbol=GET;lines=5-32].

The application also employs the **MVC (Model-View-Controller)** pattern, where API routes act as Controllers handling business logic and database interactions, while React components serve as Views [cite:file=app/workspace/page.tsx;symbol=fetchProjects;lines=28-68] [cite:file=app/api/projects/route.ts;symbol=POST;lines=30-56]. For instance, the `fetchProjects` function in the workspace page acts as the view layer initiating a request, while the `GET` handler in the projects route acts as the controller processing the database query [cite:file=app/workspace/page.tsx;symbol=fetchProjects;lines=28-68] [cite:file=app/api/projects/route.ts;symbol=GET;lines=5-45]. The **Repository Pattern** is loosely implemented through the direct use of Firestore SDK methods like `addDoc`, `setDoc`, and `updateDoc` within the API routes, abstracting the underlying database operations [cite:file=app/api/users/route.ts;symbol=POST;lines=30-70] [cite:file=app/api/users/route.ts;symbol=PUT;lines=59-79] [cite:file=app/api/projects/route.ts;symbol=POST;lines=30-56].

In the UI layer, the **Context Pattern** is explicitly used, where `useCarousel` relies on `React.useContext(CarouselContext)` to access state and API methods provided by the parent `Carousel` component [cite:file=components/ui/carousel.tsx;symbol=useCarousel;lines=35-75]. Additionally, the **Compound Components** pattern is visible in form elements, where `FormLabel` uses a `useFormField` hook to access shared form state and IDs, allowing it to function as an independent piece that relies on a parent form context [cite:file=components/ui/form.tsx;symbol=FormLabel;lines=90-130].

## 5. Technology stack and dependencies

The application is built using Next.js, as indicated by the `next build` and `next dev` scripts in the package.json [Background]. It utilizes TypeScript for type safety, with the majority of the codebase consisting of `.tsx` and `.ts` files [Background] [cite:file=components/ui/use-toast.ts;symbol=genId;lines=27-67]. For state management and UI components, the project relies on Radix UI primitives, including `@radix-ui/react-accordion`, `@radix-ui/react-alert-dialog`, and `@radix-ui/react-avatar` [Background]. Form handling is managed by React Hook Form, with validation resolvers provided by `@hookform/resolvers` [Background] [cite:file=components/ui/form.tsx;symbol=useFormField;lines=45-85].

Authentication is handled by Clerk, specifically using the `@clerk/nextjs` package, which integrates with the Next.js middleware and API routes [Background]. The backend database is Firestore, accessed via SDK methods such as `addDoc`, `getDoc`, and `updateDoc` within the API routes [cite:file=app/api/generate-slide/route.ts;symbol=POST;lines=7-47] [cite:file=app/api/users/route.ts;symbol=POST;lines=30-70] [cite:file=app/api/users/route.ts;symbol=PUT;lines=59-79] [cite:file=app/api/projects/route.ts;symbol=POST;lines=30-56]. For AI capabilities, the project uses the `@ai-sdk/google` package to interact with Google's AI services [Background] [cite:file=components/workspace/project-card.tsx;symbol=ProjectCard;lines=21-61]. Image processing is facilitated by ImageKit, with the `buildImageKitUrl` function constructing transformation URLs [cite:file=lib/imagekit.ts;symbol=buildImageKitUrl;lines=7-44]. The UI styling and layout are supported by Tailwind CSS, evident from the utility classes used in components like `SidebarInset` and `BreadcrumbItem` [cite:file=components/ui/sidebar.tsx;symbol=SidebarInset;lines=307-347] [cite:file=components/ui/breadcrumb.tsx;symbol=BreadcrumbItem;lines=24-64]. The carousel functionality is powered by the Embla Carousel library, wrapped within the `Carousel` component [cite:file=components/ui/carousel.tsx;symbol=Carousel;lines=45-85].
