## 1. Overall purpose and architecture

This application is a school management system built with Spring Boot 3.4.12, utilizing Java for the backend logic and JSP for the presentation layer [C10]. The project follows a standard Model-View-Controller (MVC) architecture, where the controller layer handles HTTP requests and view resolution, while the service layer manages business logic and the repository layer handles data persistence [C22, C24]. The system supports three distinct user roles: administrators, teachers, and students, each with dedicated controllers and dashboards to manage their specific interactions with the platform [C6, C7, C18].

The codebase is organized into a standard Maven project structure, with Java source files located under `src/main/java/com/example/demo` [C10]. The architecture enforces a strict separation of concerns; for instance, the `AdminController` does not contain direct database access but instead delegates all data retrieval and manipulation tasks to the `AdminService` [C22, C23, C24]. The `AdminServiceImpl` class acts as a facade, aggregating access to multiple repositories such as `StudentRepository`, `TeacherRepository`, and `ClassroomRepository` to simplify the dependencies for the controller layer [C2, C19, C20]. Data persistence is managed through Spring Data JPA repositories, where methods like `findAll()` and `findById()` are used to interact with the database, with `findById` returning an `Optional` to handle potential null values gracefully [C19, C20, C21].

## 2. Key components/modules

*   **Application Entry Point**: The `FinalProjectApplication` class serves as the main entry point, using `SpringApplication.run` to initialize the Spring context and start the web server [C10].
*   **Authentication and Login**: The `LoginController` manages the authentication process by displaying the login page and verifying user credentials via `AuthService` [C8]. Upon successful login, it stores the user's role and ID in the HTTP session to maintain state across requests [C8].
*   **Administration Module**: The `AdminController` oversees administrative functions, including displaying counts of students, teachers, and classrooms on the dashboard [C7]. It delegates business logic to `AdminServiceImpl`, which provides methods like `getAllCourses` and `getClassroomById` to fetch data from the respective repositories [C2, C19, C20]. This module also handles specific operations such as marking holidays via the `markHoliday` endpoint, which parses date and reason parameters before saving the record [C17].
*   **Teacher Module**: The `TeacherDashboardController` handles requests for the teacher interface, retrieving the teacher's email from the session to verify authentication and populating the model with details [C18]. The `TeacherService` supports this by interacting with `TeacherRepository`, `CourseRepository`, and `AttendanceRecordRepository` to provide data for the dashboard and attendance views [C1]. A specific method, `viewAttendance`, retrieves records for a given course and classroom, throwing runtime exceptions if the entities are not found to ensure data consistency [C16].
*   **Student Module**: The `StudentDashboardController` manages the student interface, utilizing `AuthService` and `AttendanceRecordRepository` to fetch attendance data based on the session and optional date parameters [C6]. The `StudentService` provides functionality to retrieve lists of students belonging to a particular classroom using the `findByClassrooms_ClassroomId` query [C11].
*   **Attendance Management**: The `AttendanceService` manages attendance records by marking students as present or absent for a specific course and date [C13]. It retrieves students via `studentRepo.findStudentsByCourseId` and updates their status based on the provided list of present IDs [C13].
*   **Domain Entities**: The `Student` entity defines the student profile with validation annotations like `@NotBlank` to ensure data integrity [C4]. The `Teacher` entity models the teacher profile and includes helper methods like `addCourse` to maintain bidirectional relationships with courses [C5, C14]. The `AttendanceRecord` entity links a student and a classroom to a specific date and status, serving as the core data structure for tracking participation [C3].
