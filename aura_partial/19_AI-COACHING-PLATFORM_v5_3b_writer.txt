### Authentication and User Provisioning
The application initiates the user journey through a centralized authentication layer. The `AuthProvider` component wraps the application and utilizes the `useUser` hook to detect authenticated sessions [C9]. When a user is detected, the system triggers the `createNewUser` callback, which executes the `api.users.CreateUser` mutation to persist user details, such as name and email, into the backend [C9]. This process establishes the foundational user context required for subsequent interactions, ensuring that all downstream actions are associated with a specific user identity [C9].

### Session Initialization and Navigation
The primary entry point for creating a new interaction is the `UserInputDialog` component, which manages local state for a `selectedExpert`, a `topic`, and a `loading` status [C7]. This component receives `children` and a `coachingOption` as props to customize the input interface [C7]. When the user proceeds, the `onClickNext` handler invokes the `api.DiscussionRoom.CreateNewRoom` mutation via `useMutation` [C7]. This action generates a new discussion room, after which the application navigates to the specific room view identified by the `roomid` parameter [C7].

### Real-Time Data Retrieval and State Management
Within the `DiscussionRoom` view, the system orchestrates real-time data retrieval. The component retrieves the `roomid` from URL parameters using `useParams` [C2]. It utilizes React Query hooks to fetch discussion room data and previous transcripts, and to manage the saving of new transcripts via a mutation [C2]. Simultaneously, the component initializes local state for the selected `expert`, microphone enablement (`enableMic`), and the current `transcript` string [C2]. This setup prepares the environment for real-time voice processing by establishing the necessary data context before any audio input is handled [C2].

### Voice Interaction and AI Processing
The core processing logic for voice interaction is handled by the `startListening` function, which leverages the Web Speech API [C10]. It checks for browser support, instantiates `webkitSpeechRecognition`, and configures it for continuous listening with interim results [C10]. As audio is processed, the `onresult` event handler updates the local `transcript` state with the recognized text [C10].

This raw text is then passed to the `AIModel` service, an asynchronous function that constructs a prompt by finding a matching `CoachingOption` and replacing a `{user_topic}` placeholder with the provided `topic` [C3]. The `AIModel` function sends a request to the OpenAI API using the model `deepseek/deepseek-chat-v3-0324:free`, with a message array containing the constructed prompt as an assistant message and the user's `msg` as a user message [C3].

### Multimodal Output and UI Rendering
The system provides multimodal output by converting the AI's text response into audio. The `speakResponse` function utilizes the `SpeechSynthesisUtterance` API to vocalize the generated text [C13]. It handles specific language code mappings, such as mapping 'te-IN' to 'te', to ensure correct pronunciation [C13]. Additionally, it manages the speech synthesis lifecycle by canceling any ongoing speech before starting a new utterance [C13].

The conversation interface is rendered by the `ChatComponent`, which displays a header with a "Conversation" title and a bot icon [C6].
