## 1. Overall purpose and architecture

The `trading_bot` repository is a Python-based algorithmic trading system designed to backtest various technical analysis strategies against historical market data. It solves the problem of evaluating trading logic by simulating realistic market conditions, including concurrent position management and strict risk enforcement. The primary users are quantitative analysts and developers who need to validate strategy performance before live deployment. The tech stack is dominated by Python, which accounts for 19% of the codebase, while 76% consists of CSV data files and 3% YAML configuration files [C1, C4, C17]. The system relies on libraries such as `pandas` for data manipulation, `yfinance` for data retrieval, and `pytest` for testing [C2].

The architecture follows a modular design where configuration ingestion, data retrieval, strategy execution, and risk validation are decoupled. The control flow begins with the `main` function in `run_backtest.py`, which loads a YAML configuration using `load_backtest_config` [C3, C24]. This function validates the file path and constructs a `BacktestConfig` object, raising a `FileNotFoundError` if the path is invalid [C23, C24]. The configuration is then passed to strategy instances, such as `BullishTrendContinuationStrategy`, which initializes with specific parameters like `trend_days` [C21, C22]. The `BacktestEngine` orchestrates the execution, processing market data candle by candle and coordinating signal generation with order processing [C1]. The data layer uses a `CSVDataSource` to read OHLCV data from local files, abstracting the storage behind a `get_candles` method that returns domain objects [C4, C26]. Finally, results are parsed by `_parse_csv_result` and displayed by the `result_printer` module, which extracts metrics like `max_dd` and `total_trades` [C9, C11, C12, C25].

## 2. Key components/modules

*   **`src/backtest`**: This module handles the core simulation and reporting logic. The `BacktestEngine` class manages the execution loop, enforcing risk limits and prioritizing exits over entries [C1]. The `config_reader.py` file contains `load_backtest_config`, which parses YAML files into configuration objects, extracting sections for data, strategy, and risk [C17, C24]. The `result_printer.py` module is responsible for post-execution analysis, using `_parse_csv_result` to read backtest outputs and variables like `strategy`, `max_dd`, and `total_trades` to format human-readable reports [C9, C11, C12, C25].
*   **`src/strategy`**: This folder contains the trading logic, built upon a base `Strategy` class that uses the Template Method pattern via `@abstractmethod` [C19, C20]. Specific strategies include `RSIMeanReversionStrategy`, which buys oversold stocks in uptrends [C5]; `ThreeDownDaysStrategy`, which identifies selling exhaustion [C6]; `BullishHaramiStrategy` and `BullishMarubozuStrategy`, which detect specific candlestick reversal patterns [C7, C8]. Each strategy accesses its parameters through a `config` property [C19, C20].
*   **`src/data`**: The `market_data.py` file implements the `CSVDataSource` class, which reads historical OHLCV data from local CSV files organized by stock symbol [C4]. The `get_candles` method filters data by symbol and date range, returning a list of `Candle` objects to the engine [C26].
*   **`src/risk`**: This module enforces capital safety. The base `risk_engine.py` provides a `validate` method that checks general rules like stop loss positivity [C13]. The `FixedFractionalRiskEngine` extends this to validate orders against fixed fractional risk rules [C14]. The `intraday_risk_engine.py` contains `IntradayRiskEngine`, which applies specific constraints for intraday trading, ensuring portfolio equity is positive [C15, C16].
*   **`tests`**: The `test_bullish_marubozu.py` file contains the `TestBullishMarubozuStrategy` class, which verifies the accuracy of pattern detection logic using `pytest` fixtures [C2].
*   **`configs`**: This directory stores YAML files that define the parameters for each backtest run, such as `bullish_harami.yaml` and `rsi_mean_reversion.yaml` [C17].
*   **`run_*.py`**: Top-level scripts like `run_backtest.py` and `run_position_study.py` serve as entry points. `run_backtest.py` executes a single backtest based on a provided config path [C3]. `run_position_study.py` uses a `make_temp_config` utility to generate temporary configurations for testing different position limits, accumulating outcomes in a `results` list [C10, C18].
