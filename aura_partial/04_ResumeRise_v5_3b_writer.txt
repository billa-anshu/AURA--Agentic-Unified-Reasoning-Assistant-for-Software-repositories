## 3. Notable functions/classes

The `match_resume_ml` endpoint in the backend serves as the primary entry point for AI-driven resume analysis. It accepts a PDF resume and a job description, extracting text from the PDF using PyPDF2 to prepare the data for skill matching [C1]. This function is critical because it bridges the gap between raw document uploads and the Groq AI service, which is initialized via the `groq_client` variable that retrieves the API key from environment variables [C13]. On the frontend, the `handleFileChange` function ensures data integrity by validating that the uploaded file is a valid PDF before setting the state, preventing non-PDF files from entering the processing pipeline [C6]. This validation is essential for maintaining the stability of the resume matching feature, as it stops invalid inputs before they reach the backend [C6].

The `handleStartInterview` function in the interview setup page validates that both a resume file and a job description are provided before constructing a FormData object to initiate the interview setup [C5]. This step acts as the primary trigger for generating interview questions, ensuring that all necessary inputs are present before proceeding to the next stage [C5]. To support this flow, the `handleInputChange` function updates the state of input fields and clears any existing error messages when the user types, ensuring the form remains responsive and previous validation errors are dismissed [C8].

In the mock interview environment, the `loadInterviewConfig` hook retrieves interview configuration and questions from either the location state or sessionStorage to initialize the session [C3]. This ensures the interview is properly configured with the correct questions before starting [C3]. The `initCamera` function requests media permissions and binds the video stream to a DOM element, preparing the interface for real-time processing [C17]. Once the interview segment ends, the `stopCapturingFrames` function halts the video frame capture process by clearing the interval reference and updating the state, which is essential for managing browser resources [C14]. The `generateNextQuestion` function takes the final transcribed text, along with analysis data and face analysis data, to update the conversation state by appending a new object that captures the question, transcription, emotion, score, and feedback [C18].

For visual feedback, the `getScoreColor` function returns a specific text color class based on a numerical score, using green for high scores, yellow for medium, and red for low [C10]. This is complemented by the `getScoreBg` function, which determines the border and background color classes for score indicators based on performance thresholds [C11]. Similarly, the `getEmotionColor` function maps detected emotional states, such as confident or nervous, to corresponding Tailwind CSS color classes to visually represent the candidate's emotional tone [C9]. The `handleScroll` event listener monitors the window's scroll position to update the header's styling when the user scrolls more than 50 pixels, enabling a dynamic header effect on the homepage [C4]. Finally, the `generateFinalReport` function compiles user responses, transcriptions, feedback, scores, and emotional data into a payload to generate a final interview report [C2].

## 4. Data flow and design patterns

A typical request flow begins when a user uploads a resume on the `ResumeMatchPage`. The `handleFileChange` function validates the file type, and if valid, the data is sent to the backend [C6]. The backend receives this data in the `match_resume_ml` endpoint, which extracts text and uses the `groq_client` to perform AI analysis [C1, C13]. The results are returned to the frontend, where functions like `getScoreColor` and `getScoreBg` process the numerical scores to apply appropriate visual styles [C10, C11].

In the mock interview flow, the `handleStartInterview` function validates inputs and initiates the setup [C5]. The `loadInterviewConfig` hook then loads the necessary questions from storage [C3]. During the interview, `initCamera` starts the video stream [C17], and `generateNextQuestion` updates the conversation state with new analysis data [C18]. When the interview concludes, `stopCapturingFrames` releases the video resources [C14], and `generateFinalReport` aggregates the session data for the final review [C2].

The application utilizes a standard Model-View-Controller (MVC) architecture, separating the user interface from the business logic [C6, C17]. The frontend acts as the View layer, handling user interactions and data collection [C6]. The backend serves as the Controller and Model layer, implemented using the FastAPI framework [C12]. The design patterns include the Middleware pattern, as seen in the FastAPI application setup where `app.add_middleware` is called to intercept requests [C12]. The frontend exhibits a Component-based pattern with local state management, where functions like `handleFileChange` and `initCamera` manage specific UI states and side effects [C6, C17]. The backend follows a Request-Response pattern, where specific endpoints like `generate_final_feedback` process structured input and return processed results [C16]. In this endpoint, the system calculates a total and average score by iterating through the provided responses and constructs a transcript string by enumerating the questions and answers [C16].

## 5. Technology stack and dependencies

The backend is built using FastAPI, a modern Python web framework, which is instantiated as the `app` variable titled "ResumeRise API" [C12]. The `uvicorn` library is used as the ASGI server to run the FastAPI application. The `groq` library is utilized to interact with the Groq AI service, initialized via the `groq_client` variable [C13]. `PyPDF2` is used for extracting text from PDF resumes in the `match_resume_ml` endpoint [C1]. The `python-dotenv` library is used to load environment variables, such as the Groq API key [C13]. `python-multipart` is required for handling file uploads in the FastAPI endpoints [C1].

The frontend is built with React, as evidenced by the component structure and JSX files [C7]. The `App` component defines the main routing structure of the application, mapping specific URLs to pages such as Home, Resume Match, and Mock Interview [C7]. Tailwind CSS is used for styling, with utility classes like `text-green-400` and `border-green-500` applied dynamically based on score and emotion data [C9, C10, C11]. The `postcss` and `tailwind.config.js` files indicate the use of PostCSS for processing CSS. The frontend also uses `react-router-dom` for navigation, as seen in the `Router` and `Routes` components in `App.js` [C7]. The `package.json` file lists the dependencies for the frontend, including React and related libraries. The `vercel.json` file indicates that the application is deployed on Vercel. The `Dockerfile` and `Procfile` in the backend directory suggest that the backend is containerized and can be deployed on platforms like Render or Heroku. The `render.yaml` file provides configuration for deploying the backend on Render.
