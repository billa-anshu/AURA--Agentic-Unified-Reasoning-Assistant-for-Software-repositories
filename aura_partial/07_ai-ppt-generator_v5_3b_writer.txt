## 3. Notable functions/classes

The `AIGenerationDialog` component serves as the primary interface for initiating AI-driven content creation by managing local state for the user's prompt, desired slide count, and loading status [C1]. Upon form submission, it triggers the `handleGenerate` function, which validates that the prompt is not empty before proceeding [C12]. This function then sets the loading state to true and sends a POST request to the `/api/generate-slide` endpoint, passing the prompt, slide count, and streaming preference as parameters [C12]. On the server side, the `POST` handler in the generate-slide route first verifies user authentication via the `auth()` function to ensure only authorized users can access the service [C15]. It then retrieves the user's document data from the Firestore database to process the generation request, acting as the bridge between the frontend dialog and the AI service [C15].

For project management, the `fetchProjects` function operates within a `useEffect` hook on the workspace page, fetching data from the `/api/projects` endpoint upon component mount [C16]. The corresponding `GET` handler in the projects route queries the Firestore `projects` collection, filtering documents where the `createdBy` field matches the authenticated user's ID [C3]. When creating new projects, the `POST` handler in the projects route constructs a new document containing the title, description, and metadata, using `addDoc` to persist this data into the database [C22].

The `DesignStyleSelector` component renders a modal dialog that allows users to choose a visual design style from a grid of options [C7]. When a user selects a style, it triggers the `handleDesignStyleChange` function, which updates the application's design style state and immediately persists the change by calling `saveProject` with the current slides, title, and new style [C11]. For image manipulation, the `ImageTransformDialog` component provides an input for the image URL and a selector for the transformation type, handling the asynchronous process of transforming the image [C8]. The `buildImageKitUrl` utility function supports this by constructing an ImageKit URL with transformation parameters such as width, height, and quality, returning the original URL if the service is not configured [C4].

The `Carousel` component wraps the Embla Carousel library to provide a responsive, scrollable container for displaying content [C14]. It exposes an API for controlling navigation and selection, which is accessed by child components through the `useCarousel` custom hook [C13]. This hook ensures proper component hierarchy by throwing an error if the context is missing, enforcing that it is used within a valid `<Carousel />` parent [C13].

## 4. Data flow and design patterns

A concrete end-to-end request flow begins when a user submits a prompt in the `AIGenerationDialog` component [C1]. The `handleGenerate` function captures this input and sends a POST request to the `/api/generate-slide` endpoint [C12]. The server-side `POST` handler receives this request and first executes the `auth()` function to verify the user's identity [C15]. If authentication fails, the system rejects the request; if successful, it retrieves the user's document using `getDoc` to check their current status or credits before proceeding with generation logic [C15]. This pattern demonstrates the **Middleware** or guard pattern, where every protected route begins by calling `auth()` and checking for a valid `userId` before executing further logic [C15, C19, C21, C22, C25].

The application also employs the **MVC (Model-View-Controller)** pattern, where API routes act as Controllers handling business logic and database interactions, while React components serve as Views [C16, C22]. For instance, the `fetchProjects` function in the workspace page acts as the view layer initiating a request, while the `GET` handler in the projects route acts as the controller processing the database query [C16, C3]. The **Repository Pattern** is loosely implemented through the direct use of Firestore SDK methods like `addDoc`, `setDoc`, and `updateDoc` within the API routes, abstracting the underlying database operations [C19, C21, C22].

In the UI layer, the **Context Pattern** is explicitly used, where `useCarousel` relies on `React.useContext(CarouselContext)` to access state and API methods provided by the parent `Carousel` component [C13]. Additionally, the **Compound Components** pattern is visible in form elements, where `FormLabel` uses a `useFormField` hook to access shared form state and IDs, allowing it to function as an independent piece that relies on a parent form context [C24].
