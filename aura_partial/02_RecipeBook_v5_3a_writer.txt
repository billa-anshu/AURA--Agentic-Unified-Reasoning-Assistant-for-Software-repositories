## 1. Overall purpose and architecture

The Recipe Book application is a single-page web interface designed to allow users to search for, view, and save recipes from an external database. It serves as a digital cookbook where users can authenticate to access specific features and manage a personal list of favorite meals. The project is built using the React framework, specifically bootstrapped with Create React App, and utilizes React Router for client-side navigation. The primary programming language is JavaScript, which constitutes the majority of the codebase, supported by CSS for styling and JSON for configuration.

The application follows a component-based architecture where the root `App` component manages global state and routing. The folder structure separates the application logic into a `src` directory, with a dedicated `Components` subfolder housing the individual UI modules. The `App` component initializes the application by setting up the `Router` and defining the shared state variables `isLoggedIn` and `favorites` [C4]. This centralization of state allows different components to share data, such as the user's authentication status and their list of saved recipes, without requiring direct communication between sibling components. The data flow is primarily unidirectional, with the `App` component passing state and state-updating functions down to child components via props.

## 2. Key components/modules

*   **App**: The root component responsible for initializing the application's global state and routing structure. It defines the `isLoggedIn` and `favorites` state variables and wraps the application in a `Router` context [C4]. It connects to all other modules by providing the necessary props for authentication and favorite management.
*   **Login**: A functional component that handles user authentication. It manages local state for `formData` using the `useState` hook and utilizes the `useNavigate` hook for redirection [C1]. The `handleChange` function updates the form data based on user input [C10], while the `handleSubmit` function validates credentials against hardcoded values and updates the global `isLoggedIn` state via the `setIsLoggedIn` prop [C9]. Upon successful login, it redirects the user to the `/recipes` route [C1].
*   **Recipes**: The primary interface for searching and displaying recipe data. It manages local state for `recipes`, `search`, `loading`, and `selectedRecipe` [C3]. The `fetchRecipes` function executes an asynchronous HTTP GET request to the TheMealDB API to retrieve meal data based on a query parameter [C8]. It also includes a `toggleFavorite` function that updates the global `favorites` array by adding or removing items based on their `idMeal` [C11]. This component receives `favorites` and `setFavorites` as props from the `App` component to maintain shared state [C3].
*   **Favorites**: A display component that renders the user's saved recipes. It receives the `favorites` array as a prop and maintains a local `selectedRecipe` state to track the active item [C2]. The component conditionally renders a "No favorites yet" message if the array is empty, or maps over the data to display recipe cards [C2].
*   **Navbar**: A static navigation component that provides the main menu and branding for the application. It renders links to various routes, including the home page, using a `nav` element with specific CSS classes [C6].
*   **Home**: A presentational component that serves as the landing page. It renders static welcome content and branding without any data fetching or complex state logic [C7].
*   **About**: A static view component that displays information about the application. It renders hardcoded text and branding elements, functioning purely as a presentational layer without any state management or API interactions [C5].
