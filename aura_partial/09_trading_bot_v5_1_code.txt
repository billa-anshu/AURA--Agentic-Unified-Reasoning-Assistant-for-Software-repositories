**BacktestEngine**
The `BacktestEngine` class orchestrates the execution of backtests by processing market data candle by candle, managing multiple concurrent positions, and enforcing risk limits like kill switches. It coordinates the sequence of signal generation, order processing (prioritizing exits over entries), and equity updates to simulate realistic trading conditions. [C1]

**RSIMeanReversionStrategy**
This strategy implements an RSI(2) mean reversion logic that buys stocks in confirmed uptrends (above the 200-day SMA) when short-term oversold conditions are detected. It exits positions when the RSI recovers to a specified threshold or if the price breaks below the trend SMA, serving as a core algorithmic trading model. [C5]

**ThreeDownDaysStrategy**
The `ThreeDownDaysStrategy` identifies buying opportunities when a stock closes lower than the previous close for N consecutive sessions, indicating short-term selling exhaustion. It optionally filters entries to stocks in confirmed uptrends using a 200-day SMA and executes immediate exits at the next open. [C6]

**BullishMarubozuStrategy**
This strategy detects the Bullish Marubozu candlestick pattern, characterized by a strong bullish candle with minimal upper and lower shadows, to signal strong buying pressure. It uses configurable tolerances for shadow size and body percentage to filter valid patterns for trade entry. [C8]

**BullishHaramiStrategy**
The `BullishHaramiStrategy` trades the two-candle Bullish Harami reversal pattern, where a smaller bullish candle is completely contained within the body of a preceding large bearish candle. It signals a potential bullish reversal after a downtrend, using specific body percentage thresholds to validate the pattern. [C7]

**CSVDataSource**
This class serves as a market data source that reads OHLCV candle data from local CSV files organized by stock symbol. It expects specific directory layouts and column headers to provide historical data for backtesting, supporting optional index and weight files for broader market context. [C4]

**FixedFractionalRiskEngine.validate**
This method validates an order intent against fixed fractional risk rules, ensuring the stop loss is valid and the portfolio equity is sufficient before allowing the trade. It acts as a critical safety gate to prevent orders that violate predefined risk parameters. [C14]

**IntradayRiskEngine.validate**
This validation method checks orders against intraday-specific risk rules, verifying that the stop loss is positive and the portfolio equity is greater than zero. It ensures that intraday trading positions adhere to strict capital and risk constraints before execution. [C16]

**main**
The `main` function in `run_backtest.py` serves as the entry point for executing a backtest by loading a YAML configuration, initializing the data source, and fetching the relevant stock symbols. It manages the high-level workflow of the backtest process, including printing progress and configuration details. [C3]

**TestBullishMarubozuStrategy**
This test class verifies the correctness of the `BullishMarubozuStrategy` by checking its ability to detect perfect Marubozu patterns with no shadows. It ensures that the strategy generates signals only when the candlestick criteria are strictly met, providing quality assurance for the pattern detection logic. [C2]

**make_temp_config**
This utility function creates a temporary configuration file by modifying an existing YAML config to force the use of a CSV data source and adjust the start date. It is used in position studies to standardize data inputs and test different maximum position limits without altering the original configuration. [C18]

**results**
The `results` variable in `run_position_study.py` is a list that accumulates the outcomes of multiple backtest runs across different configurations. It stores the performance metrics generated by the study, allowing for subsequent analysis and comparison of various trading parameters. [C10]

**strategy**
In the result printing logic, the `strategy` variable extracts the name of the trading strategy from the parsed backtest results dictionary. It is used to label the output rows, ensuring that performance metrics are correctly attributed to the specific strategy that generated them. [C9]

**max_dd**
The `max_dd` variable retrieves the maximum drawdown percentage from the backtest results entry. It is a key risk metric used in the reporting phase to evaluate the worst-case peak-to-trough decline experienced by the strategy during the backtest period. [C11]

**total_trades**
This variable extracts the total number of trades executed by the strategy from the results data. It provides a volume metric for the backtest, helping to assess the activity level and frequency of the trading strategy's signals. [C12]

**validate**
This method in the base risk engine validates an order against general risk rules, such as ensuring the stop loss is positive and the portfolio equity is sufficient. It serves as a foundational check for order validity before more specific risk engines process the intent. [C13]

**data**
The `data` variable in the config reader extracts the data source configuration section from the raw YAML dictionary. It allows the application to determine which market data provider (e.g., CSV, API) and associated parameters should be used for the backtest. [C17]
