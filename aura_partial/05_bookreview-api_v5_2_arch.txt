The application follows a standard Model-View-Controller (MVC) architecture where REST controllers handle incoming HTTP requests and delegate business logic to services or repositories. For instance, the `AuthController` exposes a `/api/auth/register` endpoint that processes registration data and interacts with `UserService` and `JwtUtil` to manage user credentials and token generation [C7]. Similarly, the `UserController` handles user-specific operations such as retrieving a user by ID, where it checks the current user's role to determine if access is granted, directly querying the `UserRepository` for the result [C19]. The `UserProfileController` also demonstrates this pattern by handling profile picture uploads, using `SecurityContextHolder` to identify the current user and `UserRepository` for persistence [C8].

Security and authentication are managed through a middleware chain implemented via Spring Security's `OncePerRequestFilter`. The `JwtFilter` intercepts requests to validate JWT tokens, utilizing `JwtUtil` and `UserRepository` to ensure the user exists and is authenticated before the request proceeds to the controllers [C22]. This filter is integrated into the application's security pipeline through the `SecurityConfig` class, which configures the `SecurityFilterChain` and defines CORS policies to allow specific frontend origins [C17, C16]. Additionally, `SecurityConfig` implements a `WebSecurityCustomizer` to explicitly ignore security checks for Swagger UI endpoints and static upload resources, ensuring that API documentation and file serving remain accessible without authentication [C15].

For OAuth2 authentication flows, the application employs a custom success handler to manage post-login redirection. The `CustomOAuth2SuccessHandler` implements `AuthenticationSuccessHandler` and is wired into the security configuration [C17, C23]. Upon successful OAuth2 authentication, this handler interacts with `UserRepository` and `JwtUtil` to generate a JWT token and redirects the user to the configured frontend URL, bridging the gap between the backend security context and the frontend application [C23].

Data persistence is abstracted through the Repository Pattern, where Spring Data JPA repositories like `UserRepository` provide standard CRUD operations. Controllers such as `UserController` and `UserProfileController` depend on these repositories to save, find, or delete user entities [C19, C20, C8]. For example, the `deleteUser` method in `UserController` enforces an admin-only constraint before calling `userRepository.deleteById`, demonstrating how the controller layer enforces business rules while the repository layer handles the actual database interaction [C20].

Finally, the application includes configuration classes for cross-cutting concerns such as API documentation and static resource handling. The `SwaggerConfig` class defines the OpenAPI specification, providing metadata for the "Book Review API" [C11, C12]. Meanwhile, `WebConfig` implements `WebMvcConfigurer` to map the `/uploads/**` URL pattern to the local file system directory, enabling the serving of uploaded profile pictures and other static assets [C24]. A simple `HealthController` also provides a `/api/health` endpoint for monitoring the application's status [C18].
