## 1. Overall purpose and architecture

This application is a virtual tour creation and viewing platform that allows users to upload room images, stitch them into panoramic views, and navigate through them using a 3D interface. The system serves content creators who need to build immersive digital tours and end-users who wish to explore these environments. The technology stack consists of a React frontend for user interaction and a Python Flask backend for server-side processing, with Supabase acting as the central data store and authentication provider. The codebase is primarily composed of JavaScript for the frontend logic, Python for the backend services, and image assets that constitute the bulk of the repository files.

The architecture follows a client-server model where the frontend handles UI state and user events, while the backend manages business logic and external service integration. The project is organized into two main directories: `frontend` and `backend`. The `frontend` folder contains the React application, including pages for login, tour creation, and viewing, as well as components for modals and protected routes. The `backend` folder contains the Flask application, configuration files, and the logic for processing and storing tour assets. Data persistence is handled through Supabase, which abstracts the underlying database and storage logic, allowing both the frontend and backend to perform CRUD operations without managing raw SQL or file system details directly [C14, C16]. The backend also utilizes local temporary storage folders for intermediate file processing before uploading assets to the cloud [C13].

## 2. Key components/modules

*   **Frontend Authentication and Navigation**: The `Login.js` and `Signup.js` pages handle user identity management. The `handleLogin` function authenticates users by calling `supabase.auth.signInWithPassword` and verifies email confirmation status before granting access [C5]. Similarly, `handleSignup` processes registration via `supabase.auth.signUp` and manages error states for new accounts [C3]. The `Home.js` page includes a `handleCreateClick` function that checks authentication status; if the user is not logged in, it redirects them to the login page, otherwise it navigates to the tour creation route [C6].

*   **Tour Creation and Management**: The `VirtualTourForm.js` component allows users to create new tours by generating a unique `tourId` using `uuidv4` and managing room names and image uploads [C2]. It uses `FileReader` to process file inputs and create image previews for the user [C2]. The `AllToursPage.js` component displays a list of available tours by fetching `tour_id` and `tour_name` from the Supabase `tour` table, ordered by creation date [C7].

*   **Tour Editing and Asset Management**: The `TourEditorPage.js` is the primary interface for modifying existing tours. It uses `useParams` to identify the specific tour and `useRef` to manage panorama references [C4]. Within this page, the `handleAudioFileChange` function updates local state by storing selected audio files and clearing previous recordings for specific rooms [C15]. The `handleRemoveMarker` function deletes navigation markers from the Supabase `markers` table after prompting the user for confirmation [C12]. Additionally, `handleSelectRoomForTooltipEdit` prepares the UI for editing tooltips by resetting inputs for new content and placement positions [C11]. When placing tooltips, the application calculates normalized coordinates (`x`, `y`) based on the image's bounding rectangle and inserts records into the `tooltips` table via the Supabase client [C16, C17].

*   **Backend Processing and Storage**: The `backend/app.py` file serves as the processing layer. The `get_tour_data_endpoint` retrieves specific tour data, such as the `start_room`, from the Supabase `tour` table and returns it as a JSON response [C1]. The `delete_audio_endpoint` processes POST requests to delete audio files from Supabase Storage by extracting `tourId` and `roomName` from the JSON payload [C9]. The backend also manages the stitching process, where it uploads stitched panoramas to Supabase Storage and stores the resulting `panorama_url` for retrieval [C14]. Configuration constants like `UPLOAD_FOLDER` and `TEMP_OUTPUT_FOLDER` are used to handle temporary local storage for intermediate files [C13]. During tour creation, the backend checks if a tour exists in the database and inserts a new entry using the `tour_name` from the request form if necessary [C10].

*   **Virtual Tour Viewing**: The `PanoramaViewer.js` component serves as the primary interface for users to navigate the virtual tour. It initializes a 3D viewer, manages node states, and handles audio playback for specific locations using the `tourId` retrieved from route parameters [C8].
