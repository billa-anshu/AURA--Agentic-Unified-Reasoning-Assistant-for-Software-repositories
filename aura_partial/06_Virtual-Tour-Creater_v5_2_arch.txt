The application follows a standard client-server architecture where the frontend handles user interaction and the backend manages business logic and external service integration. The flow begins with user authentication, where the `handleLogin` function in the frontend initiates a request to Supabase Auth using `signInWithPassword` [C5]. Upon successful authentication, the user proceeds to the `TourEditorPage`, where they can manage tour assets. For example, when a user selects an audio file via the `handleAudioFileChange` function, the frontend updates its local state by storing the file in `selectedAudioFile` and clearing any previously recorded audio for that specific room [C15].

The backend, implemented in `backend/app.py`, serves as the processing layer for asset management. It defines a `delete_audio_endpoint` that accepts POST requests to `/delete-audio` [C9]. This endpoint parses the JSON payload to extract `tourId` and `roomName`, validates their presence, and then constructs a Supabase storage path to delete the corresponding audio file [C9]. The backend also manages temporary local storage through configuration constants such as `UPLOAD_FOLDER` and `TEMP_OUTPUT_FOLDER`, which are used to handle intermediate files before they are processed or uploaded [C13].

Data persistence and asset storage are primarily handled through Supabase, acting as the central data store. The backend uploads stitched panoramas to Supabase Storage via the `supabase.storage.from_` method, storing the resulting `panorama_url` for later retrieval [C14]. Simultaneously, the frontend interacts directly with Supabase for certain data operations, such as inserting tooltips. In the `TourEditorPage`, when a user places a tooltip, the application calculates normalized coordinates (`x`, `y`) based on the image's bounding rectangle and inserts a new record into the `tooltips` table using the Supabase client [C16, C17].

The design patterns evident in this codebase include the **MVC (Model-View-Controller)** pattern and the **Repository Pattern** (via Supabase). The frontend components (e.g., `Login.js`, `TourEditorPage.js`) act as the View and Controller, handling UI state and user events [C5, C15, C16]. The backend `app.py` acts as the Controller for server-side operations, processing requests and orchestrating interactions with the Model [C9]. Supabase serves as the Model/Repository, abstracting the underlying database and storage logic, allowing both the frontend and backend to perform CRUD operations (like `insert` for tooltips or `upload` for panoramas) without managing raw SQL or file system details directly [C14, C16]. Additionally, the backend uses a **Service Layer** pattern where specific functions like `delete_audio_endpoint` encapsulate the logic for interacting with external services (Supabase Storage) [C9].
