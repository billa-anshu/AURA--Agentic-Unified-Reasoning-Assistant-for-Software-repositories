## 1. Overall purpose and architecture

The application is a web-based presentation editor that allows users to create, manage, and export slide decks, featuring AI-powered generation and image transformation capabilities. It is built using a Next.js stack with TypeScript, where the frontend consists primarily of React components (73% of the codebase is `.tsx` files) and the backend logic resides in Next.js API routes [C16, C22]. The system follows a client-server architecture where the browser-based interface initiates HTTP requests to server-side handlers, which then interact with a Firestore database for persistence [C16, C22].

The folder structure separates concerns between the `app` directory, which contains routing and API endpoints, and the `components` directory, which houses reusable UI elements and feature-specific modules [C1, C3]. The `app/api` folder contains route handlers for distinct operations such as project management, user authentication, and slide generation [C3, C15]. The `components/editor` folder contains the core editing tools, while `components/ui` provides foundational layout and form primitives [C5, C9]. Authentication acts as a middleware guard in the API layer, where protected routes verify user identity via an `auth()` function before executing business logic [C15, C19].

## 2. Key components/modules

*   **`app/api/projects`**: This module handles the CRUD operations for user presentations. The `GET` handler retrieves the list of projects for the authenticated user by querying the Firestore `projects` collection [C3]. The `POST` handler creates new project documents, verifying the user's identity and using `addDoc` to persist the data [C22].
*   **`app/api/generate-slide`**: This route serves as the backend entry point for AI slide generation. The `POST` handler authenticates the user and retrieves their document data from Firestore to process the generation request [C15].
*   **`app/api/users`**: This module manages user profiles and registration. The `POST` handler creates new user documents with initial fields like `credits` and `isSubscribed` [C19]. The `PUT` handler updates existing user records using `updateDoc` to merge new profile data [C21].
*   **`components/editor/ai-generation-dialog`**: This React component provides the interface for initiating AI slide creation. It manages local state for the prompt and slide count, and the `handleGenerate` function sends a POST request to the `/api/generate-slide` endpoint [C1, C12].
*   **`components/editor/outline-editor`**: The `OutlineEditor` component displays a list of slides, allowing users to select, add, or delete individual slides to manage the presentation structure [C6].
*   **`components/editor/design-style-selector`**: This component renders a modal for choosing visual design styles. It triggers the `onStyleChange` callback, which is handled by `handleDesignStyleChange` in the editor page to persist the new style [C7, C11].
*   **`components/editor/image-transform-dialog`**: This component allows users to apply transformations to images. It handles the asynchronous process of transforming images and updating the preview, integrating with the image processing service [C8].
*   **`components/editor/floating-action-tool`**: The `FloatingActionTool` renders a fixed-position button that expands to reveal quick-action tools like image transformation and content improvement [C5].
*   **`components/ui/carousel`**: This module wraps the Embla Carousel library to provide a responsive, scrollable container. The `useCarousel` hook provides access to the internal context, throwing an error if used outside a valid `Carousel` parent [C13, C14].
*   **`components/ui/sidebar`**: This module defines the layout structure, with `SidebarInset` managing the main content area and `SidebarRail` providing a toggle button to expand or collapse the navigation panel [C9, C10].
*   **`lib/imagekit`**: This utility module contains the `buildImageKitUrl` function, which constructs ImageKit URLs by appending transformation parameters like width and height to the base image URL [C4].
*   **`hooks/use-toast`**: This hook manages toast notifications, using the `genId` function to generate unique string identifiers for each notification to ensure they can be individually tracked [C2].
