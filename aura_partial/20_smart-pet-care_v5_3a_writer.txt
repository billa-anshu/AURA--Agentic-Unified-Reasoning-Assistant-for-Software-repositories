## 1. Overall purpose and architecture

The Smart Pet Care Management System is a full-stack application designed to manage pet care operations, including appointment scheduling, doctor management, and user authentication. The system serves three primary user roles: Pet Owners (Users), Doctors, and Administrators. The backend is built using Spring Boot 3, Spring Security with JWT, and Spring Data JPA, while the frontend utilizes React with Vite, Bootstrap, and Axios for API communication. The codebase is composed primarily of Java for the backend and JavaScript/JSX for the frontend, with a language composition of 33% Java, 14% JSX, and 6% JS.

The architecture follows a Model-View-Controller (MVC) pattern, where the backend controllers handle HTTP requests and the frontend services act as the data access layer for the UI [C26, C20, C13]. The application is organized into a `backend` directory containing the Spring Boot application and a `frontend` directory containing the React application. The backend entry point is the `SmartPetCareApplication` class, which is annotated with `@SpringBootApplication` and initiates the server via `SpringApplication.run` [C9, C10]. Security is managed through a stateless JWT mechanism, where the `AuthTokenFilter` intercepts requests to validate tokens before they reach the controller layer [C19]. This filter extends `OncePerRequestFilter` and extracts the token from the `Authorization` header using the `parseJwt` method [C19, C21]. If authentication fails, the `AuthEntryPointJwt` component handles the exception by returning an unauthorized error [C28]. The `WebSecurityConfig` class orchestrates this security chain, defining the `SecurityFilterChain`, disabling CSRF, and enabling CORS for the frontend origin [C12, C23].

## 2. Key components/modules

*   **Backend Controllers**: The `controller` package contains REST controllers that handle business logic. `AuthController` manages login and registration by delegating to the `AuthenticationManager` [C27]. `AppointmentController` handles appointment bookings and retrieval, using `@PreAuthorize` to enforce role-based access control for `USER` and `DOCTOR` roles [C2, C22]. The `bookAppointment` method validates the existence of the pet and doctor by calling `findById` on their respective repositories [C20]. `PetController` manages pet data, with the `getMyPets` method filtering results by the authenticated user's ID retrieved from the `SecurityContextHolder` [C25, C26]. `DoctorController` provides endpoints to retrieve all doctors or a specific doctor by ID [C16, C17, C18].
*   **Security Module**: The `security` package implements the authentication and authorization logic. `WebSecurityConfig` defines the `DaoAuthenticationProvider` and `BCryptPasswordEncoder` beans, establishing the strategy for credential verification and password encoding [C11, C12, C24]. The `AuthTokenFilter` is responsible for parsing JWTs and populating the `SecurityContext` with user details [C19].
*   **Frontend Pages**: The `pages` directory contains the main user interfaces. The `Login` component manages the authentication state and redirects users upon successful login [C8]. `BookAppointment` retrieves the `doctorId` from URL parameters and fetches the user's pets to allow scheduling [C4]. `MyAppointments` displays a list of scheduled appointments using a Bootstrap `Table` [C5]. `DoctorList` fetches and displays available doctors [C6]. `MyPets` allows users to manage pet profiles, including adding new pets via a modal [C7].
*   **Frontend Services**: The `services` directory encapsulates API interactions. `auth.service.js` contains the `register` and `login` functions, which send POST requests to `/api/auth/register` and `/api/auth/login` respectively, storing the JWT in `localStorage` upon success [C3]. `user.service.js` provides methods such as `getAllDoctors`, `getMyPets`, `addPet`, and `bookAppointment`, which map directly to the backend's REST endpoints [C13, C14, C15].
*   **Navigation**: The `Navigation` component serves as the main header, utilizing `AuthContext` to access the current user and handle logout functionality by redirecting to the `/login` route [C1].
